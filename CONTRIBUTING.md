# Contributing to Wicket

Contributions are welcome: bug reports, fixes, improvements to the skill, documentation.

## Before you start

- For anything beyond a small fix, open an issue first so the approach can be agreed before you
  write the code.
- The tools mirror the operations of the Wicket Business Central endpoint. A change that needs a
  new or different operation on the Business Central side belongs to the extension, not here.

## Layout

| Folder | What it is |
|---|---|
| `mcp/` | The MCP server (TypeScript on Bun) and its tests |
| `skills/wicket-usage/` | The usage skill — the source; `mcp/skill/`, `plugin/skills/wicket-usage/` and `docs/wicket-usage-skill.md` are generated from it |
| `plugin/` | The packaged plugin (generated by `bun run plugin:build`, except the manifest and the `orient`/`inventory` skills) |
| `.claude-plugin/marketplace.json` | The marketplace listing |

## Making a change

- **MCP server:** `cd mcp && bun install && bun test`, and `bun run typecheck`. The tests run
  without a Business Central tenant: `fetch` is stubbed per test.
- **Skill:** edit `skills/wicket-usage/` only, then run `bun run skill:sync` and
  `bun run plugin:build` from `mcp/`. The test suite fails while the generated copies are out of
  date, and when the essentials outgrow the instructions budget.
- **Plugin:** after changing the server or the skill, run `bun run plugin:build`;
  `claude plugin validate --strict plugin` checks the manifest.

Keep pull requests focused on one change, and explain *why* in the description.
